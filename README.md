# spec-pathfinder

操作路径补全 skill：把"给人看的测试用例"编译成"给智能体看的操作路径规格"，解决 AI 测试最大的卡点——**AI 不是不会点，而是不知道功能在哪里、怎么操作、什么结果是对的**。

## 干什么用

输入测试用例 Excel（+ 可选的需求文档 / 原型 / 设计稿 / 项目代码），输出三样东西：

- **人审版**（纯自然语言，零代码串）：先给人审一遍逻辑，确认"测什么、怎么测、什么算对"没错
- **agent 执行版**（含定位器、接口、文件行号、置信度）：给 Codex / Claude Code / Muse 等任何智能体按图执行
- **证据附录**：每条技术断言的出处，对账用

## 两阶段（为新需求提测设计）

- **提测前 v1（无代码模式）**：用例 + 需求/原型/设计稿探出操作路径，置信度封顶"中"，输出人审版 v1 给人审逻辑
- **提测后 v2（补证模式）**：代码到了之后逐条升级/打回置信度。立场：**代码只带路（定位、入口、信号长什么样），不定对错**；代码与需求对不上的地方进「分歧清单」，测试时按需求断言——新代码的 bug 在编译阶段就能圈出来

## 目录

- `SKILL.md`：skill 说明与全部规则（输入、两阶段、双层输出、证据分层、完成检查）
- `scripts/build-index.mjs`：项目代码索引器（Node 18+，零依赖，输出路由/模板元素/动作三表）
- `scripts/read-cases.py`：读测试用例 Excel（Python 标准库）
- `trial/`：真实 trial（llms.txt 功能 TC-0008~TC-0011）：`real/SPEC-human.md` 人审版样例、`real/SPEC.md` agent 版、`real/SPEC-evidence.md` 证据附录、`SELFCHECK.md` 验收记录
